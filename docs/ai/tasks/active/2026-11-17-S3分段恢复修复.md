# S3 分段恢复修复候选

关联 theriseunion/console-ui#3601、theriseunion/rise#256、theriseunion/camp#408。保持 Draft，不合并或部署现有采集器。

v5.1.5 的 multipart upload_from_file 不恢复 tag，而 complete_pending_uploads 对 tag 直接调用 flb_sds_len。精确源码调试构建以真实旧 metadata 复现，GDB 显示 flb_sds_len(NULL)→complete_pending_uploads:4309。此缺陷与 ARM page size 无关。

修复先从 get_upload 跳过 completion-only 对象；对未知 tag 的恢复完成使用全局互斥 claim，长度为 0。未知 tag 或已有未知 tag claim 均阻止并发访问，不伪造 tag、不删除 metadata、不跳过实际完成请求。其余已知 tag 的独立并发与 $INDEX 原有串行逻辑保持。

验证：

- 新增 multipart_restart_completion 以 S3 mock 先制造完成失败并保存实际 metadata，销毁 collector，再打开同一目录并确认完成请求及 metadata 清理。同一测试在原版退出 139、修复版退出 0。
- 原有 27 项 S3 runtime 测试全部通过；新增回归单独通过。
- 真实隔离 MinIO：固定 3.0.4 留下成功 part 1/失败后续状态，再恢复到候选，3500 条完整、无缺失重复；候选自身强杀后恢复同样 3500 条完整，恢复进程均退出 0。
- 调试构建为 amd64、最小 Tail/S3 插件，关闭 UTF-16 encoder/Kafka；它不是最终发行制品。原始固定镜像同一类型复现缺 1991/3500，不计为成功。

后续必须完成完整发行构建、两架构原生（含麒麟64KiB）、恢复失败/重试与并发、内存检查及 CAMP 安装包集成。最终镜像必须包含此源代码修复，两架构都重建，不覆盖旧 tag 或静默混用未修补的官方 amd64。

详细实验与正式结论归档在 ai-workspace 的 FluentBit在ARM上Unicode编码错误/单文件转换与持久恢复控制器设计.md；原始中间材料在忽略的 scratch。测试未升级或修改67/15/183原有Fluent Bit。
